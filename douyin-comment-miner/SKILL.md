# 抖音评论区选题挖掘

## 适用场景
用户要：看爆款视频评论、挖用户痛点、找选题方向、分析竞品视频评论、验证选题需求。
两种触发方式：
- **即时**：用户当场给链接或关键词（"现在扫一下 AI编程 的评论区"）
- **定时**：创建自动化（如每周一搜索近一周爆款），自动化 prompt 中引用本 skill 的流程即可

## 核心原则：token 高效
- **绝不**用浏览器逐屏截图读评论（验证过：单视频 80 条要 10+ 次截图，token 消耗极高）
- 采集交给本地脚本（Playwright 驱动用户本机 Chrome，约 25 秒 80 条，零 token）
- 脚本内置规则预分类（求教程/许愿/质疑/对比/共鸣），agent 只对压缩后的报告做一次分析

## 使用流程

### 1. 运行采集脚本

```bash
pip install playwright   # 依赖：playwright + 本机已安装 Chrome/Edge

# 首次使用：登录（弹出浏览器，扫码后自动检测并保存登录态）
python douyin_comments.py --login

# 指定视频链接（可多个，空格分隔）
python douyin_comments.py --url "<链接1>" "<链接2>" --max-comments 40

# 按关键词搜近一周爆款
python douyin_comments.py --keyword "AI工具" --days 7 --max-videos 3 --max-comments 40
```

- `--days N`：关键词模式只保留近 N 天发布的视频（默认 7）
- `--max-comments`：默认 40。评论区高赞置顶，前 40 条已覆盖主要高赞痛点；要全量再调大
- 输出：终端打印 `OUTPUT_MD <path>`，读取该 markdown 报告（已按点赞排序+预分类）
- 登录态持久保存在脚本目录 `.chrome-profile`，正常运行无需再次登录
- **必须用有头模式**（默认）：无头模式（--headless）会触发抖音风控，只能抓到少量评论
- 若登录态失效（评论全为 0 / 登录超时）：让用户重新运行 `--login` 扫码
- 脚本会短暂弹出并操作浏览器窗口（自动滚动评论区），属正常行为，事先告知用户不要手动干预该窗口

### 2. 分析（对报告做一次 LLM 分析）
按五分类框架解读，重点提取：
- **求教程型**（求教程/怎么弄/求文档）→ 直接对应"教程清单/系统搭建"类选题
- **许愿型**（要是能/有没有工具能）→ 未满足需求 = 差异化选题
- **质疑/对比型**（不好用/收费/不如XX）→ 反差观点结构素材 + 竞品缺陷情报
- **共鸣型**（高赞情绪评论）→ 钩子素材
- 忽略玩梗、外观评价等与主题无关的评论

### 3. 产出选题报告
每条候选选题包含：钩子一句话（结果前置）、支撑评论原文 1-3 条（含点赞数）、推荐结构（清单型/反差观点/教程拆解）、置信度（高=多视频重复出现 / 中=单视频高赞 / 低=个别提及）。

### 4. 入库（按用户的知识库偏好）
- 若用户有 Obsidian 知识库：报告存"灵感收集"目录，高置信选题进"选题库"
- 若无知识库：直接输出报告文件并在对话中给摘要

## 边界与红线
- 抖音无公开评论 API，本方案走用户自己登录的浏览器会话，低频使用；不用于高频/商业级抓取
- 单视频建议 ≤100 条、单批 ≤5 个视频，避免高频操作触发风控
- 关键词搜索模式优先选点赞 >1w、评论 >500 的视频（评论区够厚才有信号）
